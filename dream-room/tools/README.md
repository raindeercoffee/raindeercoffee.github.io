# 本機真實連線驗收

先由主控終端啟動專案的本機服務。另一個終端使用 Node.js 24 執行：

```powershell
node tools/runtime-check.mjs --slow
```

這會驗證兩房各10人、第11人拒絕、姿態同步與隔離、公開狀態不含私密憑證、兩種主動離開、斷線重連保留球與座位、同憑證接管與舊離開請求保護，以及30秒後自動推播清位。完整測試約40秒。

省略 `--slow` 可略過等待30秒的過期組。一般組仍驗證意外斷線佔席及保留期間重連。輸出會明確列出未執行的過期項目。

預設網址為 `http://127.0.0.1:8787`。更換本機埠號：

```powershell
$env:BASE_URL = 'http://127.0.0.1:8788'
node tools/runtime-check.mjs --slow
```

只接受本機網址，HTTP 請求禁止重新導向；不啟動服務、不安裝套件、不接觸正式站。兩房開跑前必須皆空；若有其他訪客，測試直接失敗，不清除別人的席位。測試使用隨機匿名憑證，失敗也會盡力以離開訊息、正常關閉及已知連線識別碼的離開介面清理；清理失敗仍以非零結束碼回報。

意外斷線使用 `4001` 關閉碼及不同於正常離開的原因，走伺服器的斷線保留流程。這是可重跑的協定層模擬，不能證明真手機鎖屏、無線網路突然中斷或正式雲端環境行為。

每次訊息等待與請求都有超時。過期組先確認27秒仍佔席，再等待房間主動推播清位；不以主動查詢觸發的清位冒充定時清位。
